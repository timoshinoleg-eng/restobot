## Deep link и tenant routing

Бот определяет ресторан через Telegram deep link при первом открытии диалога:

```
https://t.me/<bot_username>?start=<tenant_id>
```

**Пример для demo tenant:**
```
https://t.me/SwimEasy_bot?start=demo
```

При переходе по ссылке бот получает `/start demo`, извлекает `tenant_id=demo`, сохраняет его в сессии пользователя и формирует кнопку меню с правильным URL ресторана.

Если пользователь открыл диалог без deep link, бот **сначала проверяет сохранённую привязку** в БД (`telegram_user_tenants`). Если привязка есть — tenant восстанавливается автоматически. Если нет, и `TELEGRAM_BOT_DEFAULT_TENANT_ID` не задан — бот покажет инструкцию с предложением обратиться в поддержку.

Статус подтверждения на production runtime:
- production bot identity live подтверждена через Bot API `getMe`: `username = "SwimEasy_bot"`
- deep link для pilot demo: `https://t.me/SwimEasy_bot?start=demo`
- persistence/recovery path подтверждён runtime-level proof: код в image присутствует, таблица `telegram_user_tenants` существует, migration `004` применена
- live round-trip через реальный Telegram-клиент должен прогоняться оператором отдельно

### Команды после входа

После `/start <tenant_id>` бот запоминает ресторан и использует его во всех командах:

- `/menu` — кнопка «Открыть меню» с правильным tenant
- `/cart` — корзина с указанием ресторана
- `/order` — выбор типа заказа + кнопка «Оформить в приложении»
- `/my_data` — показывает данные пользователя в рамках текущего tenant
- `/delete_account` — удаляет или анонимизирует данные только в рамках текущего tenant

Если команда вызвана без предварительного `/start` — бот просит перейти по ссылке ресторана.

Ответ: Первый месяц бесплатно. Дальше переходим на платный тариф после пилота. Финальная стоимость зависит от формата использования и обсуждается отдельно, без обязательств на старте.

Follow-up: Можем начать с пилота на вашем меню. Для старта достаточно прислать актуальный список блюд и коротко описать, как сейчас принимаете заказы.

## Ветка: вопрос "что нужно от нас на старте?"

Три пункта. Первое: актуальное меню в любом виде, например файл, фото или ссылка. Второе: контакт ответственного сотрудника. Третье: короткое согласование деталей, как сейчас принимаете заказы, в какие часы работаете и что нужно показать в пилоте.
